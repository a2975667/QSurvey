# Redux State Management in QV-System React Frontend

This document explains the internal workings of Redux in the QV-System React Frontend, focusing on how slices are structured and how state flows through the application.

---

## Overview

The frontend uses **Redux Toolkit** for state management. Redux centralizes application state and logic, enabling predictable state updates and easier debugging. Slices are used to modularize state logic for different domains of the app.

### Key Concepts
- **Slice:** Encapsulates a portion of the Redux state, including its reducers and actions.
- **Store:** The global state container, combining all slices.
- **Selector:** A function to extract specific data from the store.
- **Thunk:** An async action creator for side effects like API calls.

---

## Slices in This Project

Located in `src/features/`:

- `authSlice.tsx` — Handles authentication state (user info, login status).
- `metadataSlice.tsx` — Manages survey/application metadata.

- `questionsSlice.tsx` — Handles survey questions and their state.
- `surveysSlice.ts` — Manages survey objects and their lifecycle.

## Example: Slice Structure

Each slice typically includes:
- **Initial State:** Shape of the state managed by the slice.
- **Reducers:** Functions to update state in response to actions.
- **Actions:** Automatically generated by Redux Toolkit for each reducer.
- **Async Thunks:** For API calls and asynchronous logic.

```typescript
// Example: src/features/questionsSlice.tsx
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';

const initialState = {
  questions: [],
  status: 'idle',
  error: null,
};

export const fetchQuestions = createAsyncThunk(
  'questions/fetchQuestions',
  async (surveyId) => {
    // API call logic here
  }
);

const questionsSlice = createSlice({
  name: 'questions',
  initialState,
  reducers: {
    addQuestion(state, action) {
      state.questions.push(action.payload);
    },
    // ...other reducers
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchQuestions.pending, (state) => {
        state.status = 'loading';
      })
      .addCase(fetchQuestions.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.questions = action.payload;
      })
      .addCase(fetchQuestions.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.error.message;
      });
  },
});

export const { addQuestion } = questionsSlice.actions;
export default questionsSlice.reducer;
```

---

## State Flow

1. **Dispatch Action:** UI components dispatch actions (e.g., add, update, fetch data).
2. **Reducer/Thunk:** The corresponding reducer or thunk updates the slice state.
3. **Store Update:** The Redux store is updated; subscribed components re-render with new state.
4. **Selectors:** Components use selectors to access the relevant state.

- **Predictable state updates** and debugging
