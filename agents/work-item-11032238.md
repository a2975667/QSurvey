Problem Statement
- After submitting the final QV question in a multi-question QV module, `qvNavigator.activeQuestionId` remains set (typically to the last question), despite all questions being completed. This is confusing in pure-QV flows and leaks into resume/hydration when the server snapshot is built from a pre-completion navigator state.

Observed Root Causes
- Final-submit path marks the question complete but does not clear or advance `activeQuestionId` when it is the last item in `order`.
- Reducers do not define an "all-complete" terminal state; `activeQuestionId` is always a valid ID whenever `order.length > 0`.
- Submission builds the `navigator` snapshot from the pre-completion state, so the server snapshot may be stale (missing the just-completed question and possibly pointing active to the last/next-incomplete).
- Hydration logic, when given a partial/older navigator, selects the first incomplete or (worse) fallback to the first question, never representing an "all-complete" state.

Goals (Definition of Done)
- When all QV questions in `qvNavigator.order` are marked completed, navigator reflects a terminal state: `activeQuestionId` cleared (null/undefined), and `completed` accurately set for all.
- Submission snapshot consistency: the `navigator` attached to request payloads reflects the post-submit state (i.e., includes the just-completed question and cleared active when appropriate).
- Hydration correctness: when the incoming snapshot indicates all items are completed (or the reducer can infer it), navigator ends in the terminal state (no active).
- Integration tests cover: QV-only surveys (2+ QV questions), mixed-module surveys (QV then non-QV), and resume flows with complete/incomplete snapshots.
