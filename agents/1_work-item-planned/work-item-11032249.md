Respondent Question Order Ignores Survey Sequence
ID: 11032249
Owner: Frontend
Status: Proposed
Last Updated: 2025-11-20

Problem Statement
- In the respondent flow, QV questions are always shown first, even when the survey’s `questions` array is ordered differently (e.g., Text → QV → Likert).
- The backend preserves survey order (mergeIdListWithDocList iterates `survey.questions` in order), but the frontend respondent view builds question order from `Object.values(questionsById)` and filters/sorts only QV entries, ignoring the survey’s sequence.
- Result: observed ordering mismatch; Text is saved and fetched correctly but is rendered after QV.

Current Behavior (root cause)
- `client/src/pages/survey/components/QuadraticSurveyPage.tsx` derives `questionList` from `Object.values(questionsById)` and `qvOrder` by filtering QV questions and sorting by `position`. `effectiveQuestionId` defaults to `qvOrder[0]`, so QV leads regardless of survey order.
- Designer view uses `survey.questions.map`, so the issue is specific to the respondent view’s ordering logic.

Expected Behavior
- Respondent question order should respect the survey’s `questions` array as returned by the backend (including mixed types), not reorder to put QV first.

Plan / Tasks
1) Derive respondent question order from the fetched survey’s `questions` array (preserving sequence), not from `Object.values(questionsById)` filtered to QV.
2) Update navigation logic (`effectiveQuestionId`, next/prev) to iterate that ordered list, handling mixed types (QV/Likert/Text) without forcing QV-first.
3) Add a regression test (unit or integration) that loads a survey with Text → QV → Likert and asserts the respondent view uses that sequence.

Out of Scope
- Changing designer ordering; only respondent rendering order.

Verification
- Test: respondent flow renders questions in the same order as `survey.questions` for a mixed-type survey; QV no longer forced to first.***
