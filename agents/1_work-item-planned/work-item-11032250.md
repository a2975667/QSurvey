Add Likert Question Authoring in Designer
ID: 11032250
Owner: Frontend
Status: Proposed
Last Updated: 2025-11-20

Problem Statement
- The designer UI currently only creates QV and Text questions. The backend already supports Likert creation (`POST /api/v1/protected/questions/likert`), but there is no front-end path to author or edit Likert questions in a survey.

Expected Behavior / Shape
- Create Likert: POST `/api/v1/protected/questions/likert` with body:
  ```json
  {
    "type": "likert",
    "surveyId": "<surveyId>",
    "question": "<question text>",
    "description": "<optional>",
    "scale": ["1","2","3","4","5"],   // editable list of labels/values
    "minLabel": "Strongly Disagree",  // optional
    "maxLabel": "Strongly Agree"      // optional
  }
  ```
- Update Likert: PUT `/api/v1/protected/questions/likert/:id` with same shape (fields optional).
- On success, survey.questions must include the returned `_id` from the response (no client-generated IDs).

Tasks
- Add a Likert option to the “Add question” type selector in `SurveyEdit`.
- Render the Likert form: question text, description, min/max labels, and a dropdown or editable list for scale values (default 1–5). Allow editing existing Likert questions via the same form.
- Wire create/update calls to the likert endpoints above; on success, refresh survey data.
- Display Likert questions in the designer question list (type label “Likert”; list the scale values).

Verification
- Manual: create a survey, add a Likert question, refresh designer page—question appears with correct text/scale. Edit it and confirm changes persist.
- Automated: component/integration test exercising the Likert add flow (mock fetch to `/protected/questions/likert`) and verifying the request payload includes `surveyId`, `scale`, `minLabel`, `maxLabel`.
